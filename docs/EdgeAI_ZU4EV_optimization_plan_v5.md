# EdgeAI-ZU4EV v5：端到端验证加固，以及下一轮优化在同一套验证上的推进

> 依据：2026-10-18 的 1 万张板端闭环、合成输入测试、`docs/STATUS.md`、`v4_d3.json`。v4 里仍有效的部分（逐层 trace、numpy 金模型、`e2e_compare.py`）不重复。
> 标记：**[反馈]** 你给的数；**[算术]** 用你的数直接算出；**[推断]** 必须实测；**[假设]** 我的建模假设，会被后续实验检验。

## 0. 读数：已经确立的、需要更正的、新出现的疑点

### 0.1 已经确立（可以写进状态文档的）

| 事实 | 数 | 证据强度 |
|---|---|---|
| 板端对 csim 逐比特一致 | 1 万张 GAP 全部一致；每帧复位/不复位逐 LSB 一致；0xAA 空洞 0 | 强：这是端到端最硬的一条 |
| 精度 | Keras 81.90%，csim=板端 81.78%，差 0.12 点；GAP MAE 0.026 | 强，且 1 万张，标准误差约 0.4 点 |
| 延迟 | 传输时间中位数 2.099 ms，p99 2.143 ms | 强，但**测量口径需要写清楚**（见 V2、V4） |
| 面积（布线后）| LUT as Logic 33 459（约 38%）、DSP 207（约 28%）、BRAM tile 20；WNS +0.090 ns | 强，但 WNS 裕量很薄（见 V5） |
| 3.3 点精度缺口的来源 | `BitExact=1` 流程在 1000 张上 csim 78.5%；窄精度流程 1 万张 81.78% | 强：缺口来自 BitExact 流程，不是 RF，也不是权重 |
| 已部署 bit 未被替换 | MD5 `46987907…` | 强 |

**加速比的写法：** 57.43/2.099≈27.4 倍 [算术]，但**只有两个 bit 在同一天、同一套脚本、同一个计时口径下测过才能对外写**，见 V2。对 CPU：12.23/2.099≈5.8 倍 [算术]，但 CPU 那一侧没有在同一份 1 万张上重测，**暂不能写**，见 V6。

### 0.2 需要更正：v4 的「≤1 LSB」门定得不合理

GAP 的协议标度是 1024，若 LSB 指 1/1024，那么自然图像 1 万张里 csim 对 Keras 的最大 GAP 差 0.2598 就是约 **266 LSB**。合成图上的 340、304、168、185 LSB 和这个量级相同（全黑稍大），说明**定点实现对 Keras 浮点前向本来就有这个量级的偏差**。把门设成 1 LSB，等于要求定点网络与浮点量化网络逐位一致，这个要求在非 bit-exact 流程下不成立，是我设错了。

修正后的门：

| 项 | 门 | 性质 |
|---|---|---|
| 板端 vs csim（任何输入）| **逐比特一致** | 硬门 |
| csim vs Keras（合成输入）| ≤1.5×自然图像包络（约 400 LSB）| 软门，只作提示，不作阻断 |
| csim vs Keras（自然图像 1 万张）| Top-1 差 ≤0.5 点；MAE ≤0.03 | 硬门（已通过）|

### 0.3 新出现的真问题：全黑图的板端输出与自己的 csim 不一致

- 全白、棋盘、单通道饱和：板端 = csim 逐比特一致。
- **全黑：三次上板结果相同，但与 csim 差 870 LSB（约 0.85）；csim 的非零通道位置与 Keras 一致，板端这一帧的位置不同** [反馈]。
- 这不是「硬件和浮点差一点」，而是**硬件偏离了自己的 C 模型**。1 万张自然图像全部一致，说明触发条件很窄，但它仍然是一个数据相关的硬件/C 不一致，**没有解释之前不能宣称「硬件行为完全由 csim 确定」**。
- 三次结果相同，说明是确定性的，不像读到残留数据；更像：输入打包在极值上的差异、HLS 综合后对溢出/饱和的处理与 C 仿真不同、或某条数据通路对全零数据敏感。这些是候选，**根因要靠 V3 的二分**。

### 0.4 其余值得记下的小点

1. **PL 状态 `unknown`**：重新加载同一份 bit 并设好 HP0 64 位后，前 200 张与 csim 一致，说明硬件本身没问题，是加载状态问题。要有会话启动自检（V1）。
2. **Keras 81.90%（`cifar10_bench_10k.npz`）与 B1 记录的完整测试集 81.95% 相差 5 张**：可能是 uint8 取整与 float32 的预处理差异，量级很小，但要在数据来源里写明，避免以后有人把两个数当成同一个。
3. **WNS +0.090 ns 很薄**：这个结果能复现，但换个种子或升温可能变负，需要 V5。
4. **`BitExact=1` 的问题没有被根因化**，只是被绕开了。它是一个值得留档的已知问题（hls4ml 1.3.0 + 含未量化 BN 的 QKeras 模型，bit_exact 流程在 1000 张上 csim 比 Keras 低 3.3 点）。留一个最小复现，以后升级 hls4ml 时先回归它（V8）。

## 1. 总体顺序（先加固，再优化）

| 阶段 | 内容 | 为什么这个顺序 |
|---|---|---|
| V0 | 冻结发布候选 RC1，可复现构建 | 之后所有对比都以它为基线 |

## V1. 会话启动自检（已知答案测试 KAT）

目的：每次上板的第一件事就确认「这块板上跑的是我以为的那个 bit」，并把「PL 状态 unknown」变成可检查的步骤。

**KAT 集**：22 个输入（16 张自然图像 + 6 张已确认板端=csim 的合成图，如全白、棋盘、单通道饱和），对应的 csim GAP 作为黄金答案，保存为 `kat_golden.npz`（带 bit 的 MD5）。每个 bit 一份 KAT 黄金答案。**不要把全黑放进 KAT**，在它被解释之前它会让 KAT 总是失败。

**启动流程**：

1. 读 PL 状态；不是 `operating` 就重新加载指定 bit（命令沿用你们现有的）。
2. 读并记录 PL 时钟（`pl0_ref` 或你们现有的读法），确认约 200 MHz。
3. 设置 HP0 为 64 位（沿用现有步骤）。
4. 跑 KAT：22 个 GAP 必须全部逐比特一致，才允许继续做任何测量；不一致就重载一次，再不一致就停并记录。
5. 记录板温（若可读）、时间戳、bit 的 MD5 到会话日志。

**判定「unknown」是什么**：重启一次板子，只做 `cat` 状态而不加载，记录是 `unknown` 还是 `operating`；若重启后的默认状态就是 `unknown`，那么它只是「还没加载」，不是故障，在文档里写明即可。

## V2. 旧 bit 与 RC1 同板同日前后对照

**为什么必须做**：对外要写的「前后」数字，必须在同一块板、同一天、同一个计时口径、同一份 1 万张上量。目前旧 bit 的数是 57.43 ms（N 较小），RC1 是 2.099 ms（1 万张），口径未必相同。

**步骤**：

1. 先写下计时口径：从哪个动作开始到哪个动作结束（比如「MM2S 启动」到「S2MM 完成并读回 96 B」），是否包含 PS 打包与 Dense。两个 bit 用同一个函数计时。
2. 每个 bit：V1 自检 → 1 万张（固定顺序）→ 保存 `gap.npy`、`pred.npy`、`lat_ms.npy`。旧 bit 约 9.6 分钟，RC1 约几十秒。
3. 对两组结果用 `e2e_compare.py` 做 Top-1 配对检验；再单独比较**旧 bit 与 RC1 的 GAP 是否逐比特一致**。

**判读**：

| 结果 | 含义 |
|---|---|
| 旧 GAP == RC1 GAP（1 万张）| 优化只改变了速度，函数完全不变，这是最强的回归结论 |
| 不一致，但 Top-1 相同、差异很小 | 类型/舍入有细微差别；列出差异分布，写进文档 |
| 旧 bit 的 1 万张 Top-1 明显低于 RC1 | 旧部署一直有精度缺口，对外「82%」要改写 |

**对外可写**：同一口径下的加速比，附 bootstrap 置信区间（对每帧延迟重采样）。

## V3. 合成输入覆盖与「全黑」根因

### V3.1 合成集

`make_synth_suite.py` 生成 729 张 uint8 图像（NHWC，32×32×3，固定种子），分 8 类：

| 类别 | 数量 | 目的 |
|---|---|---|
| `const_gray` | 256 | 灰度 0..255 的常数图，**找出触发全黑问题的灰度边界** |
| `const_chan` | 36 | 单通道常数 |
| `extreme_mix` | 8 | 各通道 0/255 的 8 种组合 |
| `checker` | 8 | 周期 1/2/4/8 的棋盘与反相 |
| `gradient` | 5 | 渐变 |
| `noise_uniform` | 200 | 均匀噪声 |
| `patch_mix` | 200 | 自然式底色 + 随机 0/255 方块，检验**局部极值**是否触发 |
| `near_black` | 16 | 全黑上随机 k 个像素置 v，找「差多少算不黑」|

**运行**：用现有的打包函数把它们送上板，同时跑 csim 与 Keras，三份 `gap.npy`，再：

```bash
python3 synth_report.py --suite synth_suite.npz \
  --board board_gap.npy --csim csim_gap.npy --keras keras_gap.npy \
  --scale 1024 --nat-max-lsb 266 --out results/opt_v2/v5_v3_synth.json
```

脚本给出每类的 `board_vs_csim` 失败数与最大 LSB，列出所有 hard fail，并给出 `const_gray` 中出问题的灰度集合。硬门：板端==csim；软门：csim 对 Keras 不超过 1.5 倍自然包络。

**第一判读（决定严重性）**：

| 失败分布 | 含义 | 优先级 |
|---|---|---|
| 只有 `gray_0` 与极少数极端图失败，`patch_mix`/`near_black`/`noise` 全部一致 | 触发条件很窄（严重的饱和输入）| 中：必须解释并写进已知限制 |
| `const_gray` 的低灰度区一段连续失败 | 与输入动态范围下端的饱和或回绕有关 | 高：先定位 |
| `patch_mix` 或 `noise_uniform` 也有失败 | 局部极值会触发，自然图像里也可能出现 | **最高：必须修复** |

### V3.2 根因二分（对失败的那张图，按顺序做，每步只回答一个问题）

**步骤 a：输入字节是否一致。** 把 PS 端实际发送的字节和 csim 的输入向量并排 dump（前 64 字节 + 全帧校验和）。问题：打包函数在值为 0 时的处理与 csim 的 float→定点路径是否一致（裁剪、取整、符号、补零）。自然图像一致，不能证明极值一致。

**步骤 b：是否依赖前一帧。** 在四种前置条件下发全黑图：刚复位后、跟在自然图后、跟在全白后、跟在全黑后，各 5 次。输出相同 ⇒ 与历史无关（否定静态缓冲残留）；不同 ⇒ 状态依赖，去查 line buffer、静态计数器的复位。

**步骤 c：RTL 与 C 是否一致（最关键）。** 对导出的 HLS IP 对全黑、全白、一张自然图做 C/RTL 协同仿真（cosim），比较 RTL 输出与 C 输出：

| cosim 结果 | 含义 | 下一步 |
|---|---|---|
| RTL ≠ C（全黑）| **HLS 综合后的行为与 C 不一致** | 步骤 d |
| RTL == C，板端 ≠ C | IP 本身正确，问题在 IP 之外（DMA、AXIS、BD、PS 缓冲）| 步骤 e |

**步骤 d：定位到层。** 做若干个截断的顶层（只保留前 k 层），分别做 csim 与 cosim，找第一个出现差异的层。窄精度（非 bit-exact）流程下最常见的原因是**累加器/结果类型太窄，输入取极值时溢出，综合后的位宽优化与 C 的回绕语义不同**。修法：对该层的累加器与结果类型加宽并/或设 `AP_SAT`，然后重做 V3.1 全套与 10k 板端回归。

**步骤 e：IP 之外。** 用 `near_black` 系列（只改 1 个像素）判断触发是否与「整帧全零」有关；检查 PS 缓冲是否可缓存、是否做了正确的刷新/无效化；检查 DMA 长度与 TLAST；检查数据宽度转换器；用另一种方式发送同一帧（比如把全零帧改成第 0 个像素为 1）看输出是否连续变化。

### V3.3 门

| 项 | 门 |
|---|---|
| 729 张合成集：板端==csim | 全部逐比特一致；若不能修复，必须有书面的触发条件与影响范围 |
| 修复后自然图像 1 万张 | 与 RC1 的 GAP 逐比特一致，或差异被解释并 Top-1 不降 |

**如果修复需要改类型**，则 RC1 被取代，V0 的冻结与 V2 的前后对照要重做。这也是 V3 排在 V4 之前的原因：先确定硬件功能正确，再谈性能。

## V4. 延迟分解与吞吐

**现状**：板端传输时间 2.099 ms，而 RC1 的理想周期模型是：各层周期求和 283 392 拍 = 1.417 ms，最大层 147 456 拍 = 0.737 ms（conv1b）[算术]。如果 PS 侧固定开销约 0.40 ms（早期「只读 GAP 不跑 DMA」的测量，未必适用于现在）[假设]，则 PL 部分约 1.70 ms，相当于**各层求和的 1.20 倍，或最大层的 2.3 倍**。数字更接近「各层求和」，意味着流水重叠并没有发挥作用（或者别处有额外开销）。这个结论目前只是 [假设]。

### V4.1 需要的数据

1. **RC1 的 csynth 逐层表**：每层 Latency、achieved II（确认没有第二个 conv1a 式的 II>1）、顶层 Latency/Interval。
2. **RTL cosim 的真实延迟与间隔**：至少 3 帧，读 `latency` 与 `interval`。`interval ≈ latency` ⇒ 层间没有重叠；`interval ≈ 最大层` ⇒ 重叠正常。
3. **板端分解**：

| 量 | 获取方式 |
|---|---|
| `T_ps`（PS 打包/刷新/读回/Dense）| 不启动 DMA，只跑 PS 路径的耗时 |
| `T_dma`（传输本身）| 用一个已知的纯直通 IP（或只测 MM2S→S2MM 回环）估计；没有的话从 cosim 对照倒推 |
| `T_pl`（PL 计算）| `T_board − T_ps − T_dma`，用 cosim 周期数 / 200 MHz 交叉验证 |

4. **背靠背吞吐**：连续提交 K 帧（K=100）不等上一帧返回，测每帧间隔；这是 `interval` 的板端版本。若 DMA 驱动不支持排队，用 SG 或交错提交实现。

### V4.2 判读

| 观察 | 含义 | 下一步 |
|---|---|---|
| cosim interval ≈ 最大层，板端 T_pl 远大于 cosim latency | 板端额外开销（DMA、PS）占大头 | 优化 PS 路径（C 实现、预分配、避免每帧对象分配），目标 `T_ps` ≤0.1 ms |
| cosim interval ≈ latency | 层间没有重叠 | 查 FIFO 深度与反压：浅 FIFO 会使上游频繁停顿。做 A/B：把池化与下游卷积之间的 FIFO 深度加倍/四倍，看 cosim latency 是否下降 |
| cosim 与 csynth 都说约 0.74–1.4 ms，板端 ≈2.1 ms | PS/DMA 开销被低估 | 以 `T_ps` 测量为准 |

**这一步决定 V7 的路线**：如果瓶颈是「没有重叠」，加并行度收益有限（只缩短了各层，不缩短求和的结构）；如果瓶颈是「最大层」，加并行度才有效。

## V5. 时序与环境裕量

WNS +0.090 ns（200 MHz）只能说明这一次布线通过。要证明这个 bit 稳：

1. **多种子/多策略**：用 3–5 个不同的实现策略或种子重跑布线，汇总 WNS、TNS、WHS（保持时间）、脉宽余量。若有任何一个为负，说明裕量不够。
2. **降频对照**：若 BD 允许，把 PL 时钟降到 180/160/150 MHz，各跑 KAT + 1000 张。得到延迟随频率的比例，也确认没有隐性时序问题。
3. **soak**：连续 30–60 分钟循环，每 100 帧取一张与黄金 GAP 比对（逐比特），同时记录板温。任何不一致立刻停止并保存现场。
4. **报告**：`report_timing_summary`、`report_clock_interaction`、`report_methodology`（有无 CDC 或未约束路径）。

**门**：多种子的 WNS 全部 ≥0（或明确选定的策略是可复现的），soak 无不一致。裕量不足的处理：保持 200 MHz 但换更稳的策略，或降到 187.5 MHz 并按比例报告延迟。

## V6. CPU 对照与功耗

### V6.1 CPU 对照

在 A53 上用同一份 `cifar10_bench_10k.npz`、同一顺序重跑 TFLite INT8（线程数与现有设置一致，写明）：Top-1、延迟中位数/p99，重复 3 次。写清楚计时口径是否包含预处理。输出同样格式的 JSON，与 FPGA 结果并排。**在做完之前，对外不要写「比 CPU 快 5.8 倍」。**

### V6.2 功耗

按可行性从高到低：

1. **板外在线功率计**（12 V 输入）：分别测空闲、CPU 基线运行、FPGA 运行各 60 秒，至少 3 次，FPGA 与 CPU 的功耗都用「运行 − 空闲」。
2. **板上监测**：检查 `/sys/class/hwmon` 里有没有电流/功率读数；若有，用它。
3. **AMS（系统监视器）**：通常能读温度与电压，不含电流，只能作为辅助。
4. **Vivado `report_power`**：只是估计值，必须明确标注「估计」，不能与实测并列当作结果。

没有手段就写「未测」，不要估算。J/帧 = 功率 × 每帧时间。

## V7. 下一优化候选在同一套验证上推进

**前提**：V0–V3 完成（功能正确且可复现），V4 给出了瓶颈性质。

### V7.1 现有裕量

RC1 用掉 LUT 约 38%、DSP 约 28%、BRAM 约 8%，距离 v3 设的红线（LUT<60k、DSP<500、BRAM_18K<160）还有很大空间。面积不是限制，**限制是不知道更大的并行度能不能把延迟拉下来**。

### V7.2 候选与预测（两个模型，实验会区分它们）

候选 A2-L：RF = 27 / 36 / 144 / 90 / 180 / 216（ΣP=188，`rf_planner.py` 已校验合法；全部 `RF≤n_in`，不引入 IndexLoop）。

| 模型 | 公式 | RC1 校准 | A2-L 预测 | A2-M 预测 | A2-H 预测 |
|---|---|---|---|---|---|
| 各层求和模型 [假设] | `T = 0.40 + 1.20 × Σ周期/200MHz` | 2.10 ms | **1.30 ms** | 0.92 ms | 0.78 ms |
| 最大层重叠模型 [假设] | `T = 0.40 + 2.3 × 最大层周期/200MHz` | 2.10 ms | **0.82 ms** | — | — |

（Σ周期：A2-L 149 760、A2-M 86 784、A2-H 63 744；最大层周期：A2-L 36 864。其中 0.40 ms 来自早期 PS 开销测量 [假设]。）

**做 A2-L 就能区分两个模型**：实测接近 1.3 ms ⇒ 层间基本串行，应先解决重叠（V4.2）；接近 0.82 ms ⇒ 重叠正常，只是有一个大的固定系数。

### V7.3 流程（每个候选都走这一套）

1. 同一转换流程（窄精度、同补丁），只改 `RF_PER_LAYER`；转换日志里**不得出现** `Invalid ReuseFactor`。
2. csim 前 1000 张：GAP 与 RC1 **逐比特一致**（RF 只改调度，已被证实）。
3. csynth：每层 `ReuseLoop` achieved II=1；顶层周期与 `rf_planner.py` 的预测一致。
4. 综合/布线：LUT、DSP、BRAM、WNS≥0，写入 JSON；由 RC1 与候选两点估计「每个乘法器的面积增量」，再预测下一档。
5. 板端：V1 自检 → 1 万张 → `e2e_compare.py`：**GAP 与 RC1 逐比特一致**（硬门）、延迟与预测对照。
6. 新 bit 与 RC1 并存，不覆盖。

**停手**：延迟相对上一档改善 <15%；或面积超红线；或 WNS<0；或 GAP 不再与 RC1 一致。

### V7.4 精度线（V7 之后再考虑）

硬件与 Keras 现在差 0.12 点，所以 Keras 域的训练改进可以直接转化为板端精度，B1（Q8）在 Keras 域已被否定（+0.34 点，p=0.130），保持关闭。

候选：B0（同架构的训练改进：更强的老师、KD 的 α/T 重扫、数据增强、更长训练）和 B2（加宽，先 24/28/32，MAC 约 2.06 倍）。判据沿用：1 万张配对检验 p<0.05 且净增 ≥1 点。B2 的面积用 V7.3 第 4 步得到的实测增量来估计，这一次终于有数据了。

## 附录 B：我不能判断的几点

1. **LSB 的定义**：我假设为 1/1024（协议标度）。若不是，软门的数值要按实际 LSB 重算。
2. **PS 开销 0.40 ms 是否适用于现在**：它来自早期「只读 GAP」的测量，V4 会替换它。
3. **全黑问题的根因**：我给出了二分顺序，没有数据支持任何一个候选；不要在 V3.2 完成之前改类型或 RF。
4. **cosim 在你们的环境里是否可行**：若 RTL cosim 太慢，可用更小的截断顶层与更少帧，只要能覆盖全黑帧。
